カラーシステム代替案

4.html の「透明度計算方式」がやや地味に感じたため、複数のアプローチを比較。
ボーダーの有無、グラデーション、グロー効果など様々な表現を検討する。

案 A ボーダーなし・フラット 新提案

ボーダーを完全に除去し、背景色のみでヒートマップを表現。
より洗練された最小限のデザイン。テキスト色のコントラストを上げて視認性を確保。

QWERTY（アンバー）
左手 / 子音（ブルー）
右手 / 母音（ピンク）
特徴: 変数数は最少（色相+彩度のみ）。ボーダーなしで情報密度が低く軽い印象。
懸念: レベル1〜3の低ヒートキーの境界が分かりにくくなる可能性あり。
案 B ボーダーなし + 微グロー 推奨

ボーダーを除去しつつ、高レベルキーに微妙な発光感（box-shadow glow）を追加。
フラットだが高ヒートキーに存在感がある。

QWERTY（アンバー）
左手 / 子音（ブルー）
右手 / 母音（ピンク）
特徴: ボーダーレスの軽さと、グロー効果による段階的な視覚強調の両立。
利点: 高頻度キーの「光っている感」があり、ヒートマップとして直感的。
案 C 手動チューニング（現行方式ベース）

現行の90変数方式をそのまま維持し、ボーダーのみ除去。
手動で丁寧にチューニングされた色が最も美しいが、変数管理コストは高い。

QWERTY（アンバー）
左手 / 子音（ブルー）
右手 / 母音（ピンク）
特徴: 現行のハンドクラフトされた色味を活かしつつ、ボーダーだけ除去してスッキリ。
懸念: 変数90個の管理コスト。ただし一度決めたら変更頻度は低い。
案 D 透明度計算 + ボーダーあり（4.html と同じ）

4.html で提案した透明度計算方式。参考用に再掲。
変数6個で管理できるが、均一的でやや魅力に欠ける。

QWERTY（アンバー）
左手 / 子音（ブルー）
右手 / 母音（ピンク）
特徴: 変数最少で完全自動計算。管理は楽。
懸念: 数学的に均一すぎて手動チューニングの「味」がない。
案 E カスタムカーブ計算 + ボーダーなし 6変数

透明度計算のカーブを非線形（指数的）に調整し、低レベルは限りなく暗く・高レベルに急激に明るくなるように。
ボーダーなしで、計算方式でも「手動チューニング」に近いメリハリを実現。

QWERTY（アンバー）
左手 / 子音（ブルー）
右手 / 母音（ピンク）
特徴: 非線形カーブで低ヒートキーはほぼ無色、高ヒートキーだけ目立つ。自然な印象。
利点: 変数数の少なさと見た目の品質を両立。管理しやすく美しい。
